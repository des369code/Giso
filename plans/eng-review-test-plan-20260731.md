## Affected Surfaces / Routes

- **iOS app (SwiftUI)** — card feed, trial/paywall state, settings
- **Share extension** — enqueue save from Instagram share sheet, "Saving…" → card/bare-save inline
- **Home-screen widget (WidgetKit)** — shows today's card, must match in-app card
- **Supabase Edge Function `ingest`** — URL fetch + SSRF guard + extraction + dedupe + entitlement gate
- **Supabase Edge Function `queue-cron`** — daily pick, per-user TZ scheduling, idempotency
- **Supabase Edge Function `revenuecat-webhook`** — entitlement state updates
- **Card export** — server-generated image with reel thumbnail

## Key Interactions to Verify

- Share a reel → card appears (extension shows "Saving…" first, card lands in app feed)
- Duplicate share of same reel → "Already saved", no reprocessing
- Day-1 cold start: first card fires even when first save is a bare save (music-only/meme/extraction failure)
- 3-day rediscovery cadence: FIFO, per-card window unchanged by rerank
- Trial lifecycle: first launch starts 3-day clock → 50th save blocked (trial copy) → day-4 hard lock (existing cards viewable, no new saves, no pushes) → subscribe → gate reopens
- Push-permission-denied fallback: widget + in-app "Today's card" still work
- Subscribe → RevenueCat webhook → entitlement opens within webhook latency

## Edge Cases

- Non-Instagram link in share sheet → reject toast
- ig.me / instagr.am short links → allowlisted, redirect hops validated (cap ~5), each hop host-checked
- HTTP 200 "error shell" (zero post data) → no-caption branch, NOT treated as success
- HTTP 403/429 (scraping blocked) → manual-caption fallback, user can type their own takeaway
- Deleted/expired post → "[This post is no longer available]" card with save date
- Photo post (non-reel) → bare save with "try a Reel next time" copy
- Low-info caption ("link in bio", "follow @x") → bare save via rule classifier (D1)
- Malformed JSON from Claude → 1 retry, then degrade to bare save
- Duplicate-save race (double-tap share) → unique index conflict handled gracefully
- Empty queue → no push sent
- Entitlement webhook missed → fails closed (user locked until retry); health cron surfaces it
- Trial clock: server-authoritative timestamps, not device time

## Critical Paths (must work end to end)

1. Share reel → SSRF-validated fetch → extract → structured card → dedupe → saved
2. Day-1 card → 3-day cadence → push at user-local time → card opens in app
3. Trial end → hard lock → paywall → RevenueCat subscribe → webhook → gate reopens
4. Extraction prompt change → 20-reel eval suite passes (fixtures + expected cards)

## Eval Requirements (LLM/prompt changes)

- **Extraction eval suite (permanent):** the 20-reel spike becomes fixture pages + expected cards; run on every extraction change. Dev-loop tool, not a CI gate (CEO decision).
- **Classifier cases (new, from eng review D1):** filler captions → bare save; length-floor boundary; real captions NOT demoted. Added to the same suite.
- Baselines: expected cards authored during the spike; concierge hand-written cards become a gold-standard baseline when the concierge test data exists.

## Test framework notes

- No framework exists yet (greenfield). Unit targets: Swift XCTest for iOS logic (trial-state machine, queue scheduler mirror) — or Vitest/Deno test for Edge Functions (supabase functions run Deno). Queue scheduler + extraction schema + SSRF redirect tests are the highest-value unit targets.
